## Cross-cutting implementation

Image input (`inputs.put` plus `turns.start` `inputs`) is gated twice: the selected model must report `input.image` as supported, and the session's adapter must carry images. Either failure is a typed `CAPABILITY_UNSUPPORTED` before any provider call; images are never dropped. "Fixture-tested" means request shapes checked against the loopback HTTP fixture or `acp_peer.py`; no live provider has received an image from this toolkit.

September 27 paired-browser metadata check on source `0c82138`: two distinct Codex installations returned 7 model entries each, Claude Code 11, Grok 1, and OpenCode 111 (137 route-specific entries total). Rechecking all 16 detected profiles retained the same confirmed profiles and catalogs. The earlier 130-entry review run preceded the installation-identity correction. These are provider-returned catalogs at that time, not entitlement guarantees or inference qualification. Ollama and LM Studio were detected but offline. Their accountless local execution path is covered end to end with loopback fixtures. Native ACP resumption is tested after completed turns, with failed suspension and grant-lifetime revocation handled explicitly.

The service provides separate provider, installation, profile, account, connection, route, model, billing, and quota-pool identities. It preserves evidence and stale/unknown states. Native ACP suspend/resume is offered only when the connected ACP peer advertises `loadSession`; it is not implemented for the other integrations by inheritance.

Windows and Ubuntu/WSL2 have native execution records in [release qualification](../qualification/RELEASE-CANDIDATE.md). macOS is included in the GitHub Actions platform matrix, but it is not platform-executed or qualified until a macOS job actually completes. Cross-compilation alone is not qualification. The C# HTTP consumer has been run against the Windows helper. Tauri remains an integration example rather than a separately qualified application.

Read [native Google/Grok status](native-google-grok-status.md), [Cursor cached metadata](cursor.md), and the [qualification directory](../qualification/) before treating a provider as available for a specific account or platform.

## Session-start authentication

`sessions.create` re-reads the selected connection's live account/auth status before validating the selection whenever its metadata is older than the 60-second probe cache, the way native clients judge login at session start. Hosts therefore do not depend on the 15-minute metadata freshness window: a still-valid login is re-confirmed, and a logged-out client fails with `AUTH_REQUIRED` instead of riding a stale cache. Unknown billing is still refused unless the host declares it.

## Model revisions

Model and option revisions hash only semantic catalog content (ids, controls/choices/defaults, category, scope, billing/permission sensitivity, capability ids/support). Evidence sources, client versions, timestamps and current values are excluded, so an unchanged catalog keeps its revisions across probes and helper processes.

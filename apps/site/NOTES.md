## Positioning and naming

- The brand is **OriginLM**; the repository, crates, and packages keep their existing `local-ai-kit` names. The site never calls the product "Local AI Kit" in customer-facing copy, but install commands use the real package identifiers so they are not invented.
- Both halves lead: "See your AI" and "Build with it" are peers. The comparison table names no competitors; its left column describes the category ("a single-provider usage widget"), as required by the positioning brief.
- Provider support is condensed from `docs/adapters/SUPPORT-MATRIX.md`. "Conditional" is used where the matrix says implemented-but-gated, fixture-tested only, or dependent on a reported capability. Unknown is never rendered as zero. The complete caveats live behind the "Evidence and limits" disclosure on every card and in the linked matrix.

## Deliberate calls

1. **`originlm.dev` is a placeholder.** No domain, hosting, or DNS is configured, per the brief. The install lines and footer links point at paths that will exist when deployment is approved. All repository links point at the real GitHub repo.
2. **Packages are labelled pre-release.** `@local-ai-kit/sdk`, `local-ai-kit`, and `local-ai-kit-preview` are not published yet. The install panel says to use a release bundle or build from source until the first public release rather than implying a live registry install.
3. **No audio in the video.** Music/voiceover would need a licence; the film is silent with on-screen type. This is stated in the video section.
4. **Standalone app.** `apps/site` has its own package.json and lockfile and is not in the root workspaces. `pnpm-workspace.yaml` still globs `apps/*`; CI uses npm against the root lockfile, so the site does not affect it. Do not add the site to the root workspace without coordinating with the lockfile owner.
5. **Plain CSS, no Tailwind.** The brand tokens and artwork are copied from the demo, but the landing page uses a small hand-written design system so the page shell stays independent of the demo's shadcn/Tailwind stack.
6. **3D labels are a DOM rail, not in-scene text.** The rail keeps brand typography, avoids font downloads/troika in the 3D chunk, and never overlaps the panels. It is hidden on small screens (tap/tooltip remains); the full layer list is in the accessible description.
7. **The 3D bundle split** uses Rolldown's `advancedChunks` groups (three, fiber, postprocessing, drei) so the 3D chunk group can be measured honestly. React and ReactDOM are a separate vendor chunk needed by the shell anyway.
8. **Provider grid copy** uses "Found / Auth / Usage / Models / Text / Vision / Approve / Resume" for compactness; the matrix's exact wording (including "passive detection", "native session resumption") is in the disclosure and the linked document.
